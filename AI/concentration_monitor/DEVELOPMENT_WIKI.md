# 📚 AI Concentration Monitor 개발 위키

## 1. 프로젝트 개요 및 리팩토링 (2026.01.25)
기존의 단일 파일(`run.py`)로 구성된 집중도 분석기를 유지보수성과 확장성이 높은 **모듈형 아키텍처**로 리팩토링하였습니다.

### 🏗 변경된 아키텍처 구조
*   **`core/`**: 설정(`Config`), 타입(`FocusState`), 데이터 구조 정의.
*   **`detectors/`**: 개별 행동 감지 로직 분리.
    *   `absence_detector.py`: 자리 이탈 감지.
    *   `drowsiness_detector.py`: 졸음(눈 감김, 고개 떨굼) 감지.
    *   `phone_detector.py`: 핸드폰 사용(YOLO 객체 인식 + 행동 분석) 감지.
*   **`fusion/`**: 여러 감지 신호를 종합하여 최종 상태를 판단(`StateFuser`).
*   **`scoring/`**: 상태 지속 시간에 따른 집중도 점수 계산(`FocusScorer`).
*   **`run.py`**: 메인 실행 파일 (CV 파이프라인 및 UI 담당).

## 2. 성능 튜닝 및 트러블슈팅 리포트

### 🚨 문제 상황 (Issue)
*   **현상**: 사용자가 핸드폰을 들고 있는 명확한 **"딴짓(Phone Use)"** 상황임에도 불구하고, 시스템이 이를 **"졸음(Drowsy)"**으로 오인하는 현상 발생.
*   **원인 분석**:
    1.  **시선 각도(Pitch) 임계값**: 핸드폰을 볼 때 고개를 숙이는 각도가 기존 설정(`0.60`)보다 낮아(`0.30`~`0.40`), "고개 숙임" 조건이 충족되지 않음.
    2.  **판단 우선순위**: 핸드폰을 보며 눈을 내리깔 때, `DrowsinessDetector`가 "눈이 감겼다"고 판단하여 높은 점수를 보냄. `StateFuser`가 `DROWSY`를 먼저 확정해버림.

### 🛠 해결 과정 (Solution)
`monitor_log.csv` 데이터를 분석하여 다음과 같이 로직을 개선하였습니다.

#### A. 임계값(Threshold) 최적화
*   **Pitch Threshold 완화**: `0.60` → **`0.40`**
    *   사용자의 평소 시선(`0.30`)과 딴짓 시선(`0.45`+)을 구분할 수 있도록 민감도를 조정함.
*   **Phone Confidence 활용**: YOLO 인식 신뢰도가 **`0.4`** 이상이면, 고개 각도와 상관없이 즉시 "사용 의심" 상태로 간주하도록 조건 완화.

#### B. 상태 판단 로직(Fusion Logic) 변경
*   **우선순위 역전 (`fusion/state_fuser.py`)**:
    *   **Before**: `ABSENT` > `DROWSY` > `PHONE`
    *   **After**: `ABSENT` > **`PHONE`** > `DROWSY`
    *   **논리**: 핸드폰이 감지된 상태에서 눈을 감거나 고개를 숙이는 것은 "졸음"이 아니라 "핸드폰 사용" 행동의 일부일 확률이 훨씬 높음.

### 📈 검증 결과 (Verification)
*   로그 파일(`logs/monitor_log_...csv`) 데이터 확인 결과:
    *   핸드폰을 들자마자 `phone_conf` 상승과 함께 `state`가 즉시 **`PHONE`**으로 전환됨.
    *   `DROWSY`로 튀는 현상(Flickering)이 제거됨.

## 3. 로그 데이터 사전 (Data Dictionary)
`logs/` 폴더에 저장되는 CSV 파일의 각 컬럼(열)에 대한 상세 설명입니다.

| 컬럼명 (Column) | 설명 (Description) | 값의 범위 / 예시 |
| :--- | :--- | :--- |
| **timestamp** | 기록된 시간 | `21:15:35.169` (시:분:초.밀리초) |
| **elapsed_sec** | 시작 후 경과 시간 | `sec` (초 단위) |
| **state** | **[핵심]** AI가 판단한 최종 상태 | `FOCUSED` (집중), `PHONE` (폰사용), `DROWSY` (졸음), `ABSENT` (이탈) |
| **score** | 집중도 점수 (시간에 따라 변동) | `0` ~ `100` (100점이 만점) |
| **ear** | 눈 떠짐 정도 (Eye Aspect Ratio) | `0.0`(감음) ~ `0.35`+(뜨고 있음) <br> *(보통 0.18 이하일 때 졸음 의심)* |
| **pitch** | 고개 숙임 정도 (Head Pitch) | `0.0`(정면) ~ `1.0`(완전 숙임) <br> *(보통 0.40 이상일 때 딴짓/졸음 의심)* |
| **phone_conf** | AI가 "이게 핸드폰이다"라고 확신하는 점수 | `0.0` ~ `1.0` (높을수록 확실함) |
| **hand_interaction** | 손이 핸드폰 근처에 있는가? | `1` (있음), `0` (없음) |
| **phone_in_use** | 핸드폰 사용 중 판정 여부 | `1` (사용 중), `0` (아님) |
| **drowsy_score** | 졸음 의심 점수 | `0.0` ~ `1.0` (높을수록 졸림) |
| **raw_absent** | 자리 비움 여부 | `1` (사람 없음), `0` (사람 있음) |

### 💡 데이터 분석 팁
*   **핸드폰 사용 확인**: `state`가 `PHONE`이거나, `phone_in_use`가 `1`인 구간을 찾으세요.
*   **졸음 확인**: `state`가 `DROWSY`이거나, `ear` 수치가 지속적으로 낮은 구간을 찾으세요.
