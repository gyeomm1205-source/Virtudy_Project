# Pull Request (PR) 규칙

> **목적**: 효율적인 코드 리뷰와 품질 보장을 위한 PR 작성 및 검토 가이드

---

## 📋 1. PR 제목 규칙

### 형식
```
[타입] 간결한 요약 (50자 이내)
```

### 타입 분류
- `[FEAT]`: 새로운 기능 추가
- `[FIX]`: 버그 수정
- `[REFACTOR]`: 코드 리팩토링
- `[STYLE]`: 코드 포맷팅, 세미콜론 누락 등
- `[DOCS]`: 문서 수정
- `[TEST]`: 테스트 코드 추가/수정
- `[CHORE]`: 빌드, 패키지 매니저 설정
- `[PERF]`: 성능 개선

### 예시
```
✅ [FEAT] 스터디룸 타이머 기능 구현
✅ [FIX] 집중도 분석 NaN 오류 수정
✅ [REFACTOR] MediaPipe 서비스 레이어 분리
❌ feat: add timer (너무 모호함)
❌ 타이머 추가 (타입 누락)
```

## 📝 2. PR 설명(Description) 템플릿

### 기본 템플릿
```markdown
## 📌 작업 내용
<!-- 무엇을 변경했는지 간단히 설명 -->

## 🎯 작업 목적
<!-- 왜 이 작업이 필요했는지 -->

## 🔍 주요 변경사항
- [ ] 변경사항 1
- [ ] 변경사항 2
- [ ] 변경사항 3

## 📸 스크린샷/동영상 (선택)
<!-- UI 변경 시 필수, 기능 변경 시 권장 -->

## ✅ 테스트 체크리스트
- [ ] 로컬 환경에서 정상 동작 확인
- [ ] 기존 기능 영향도 확인
- [ ] 브라우저 호환성 테스트 (Chrome, Safari, Firefox)
- [ ] 모바일 반응형 테스트 (선택)

## 📚 관련 이슈
<!-- 관련 이슈가 있다면 링크 -->
Closes #123
Related to #456

## 💡 리뷰 시 주의사항
<!-- 리뷰어가 특히 봐줬으면 하는 부분 -->
```

### 예시: Feature PR
```markdown
## 📌 작업 내용
스터디룸 타이머 기능을 구현했습니다. 25분 집중 + 5분 휴식 포모도로 타이머 지원.

## 🔍 주요 변경사항

## 📸 스크린샷
![타이머 UI](./screenshots/timer-ui.png)

- [x] 타이머 시작/일시정지/재시작 테스트
- [x] 브라우저 탭 전환 시 타이머 유지 확인
```

## 👥 3. 코드 리뷰 가이드

### 3.1 리뷰어 지정
- **최소 1명**, **권장 2명**
- 역할별 리뷰어:
  - UI 변경: **UI 담당자**
  - API 연동: **Backend 담당자**
  - AI/MediaPipe: **AI 담당자**
  - 공통: **Tech Lead**

### 3.2 리뷰 체크리스트

#### 🔍 기능 검토
- [ ] 의도한 대로 동작하는가?
- [ ] 엣지 케이스가 고려되었는가?
- [ ] 에러 처리가 적절한가?

#### 📐 코드 품질
- [ ] 코드가 읽기 쉽고 이해하기 쉬운가?
- [ ] 중복 코드가 없는가?
- [ ] 네이밍이 명확한가? (변수, 함수, 컴포넌트)

#### 🏗️ 아키텍처
- [ ] FSD 구조를 준수하는가?
- [ ] 컴포넌트 책임이 명확한가?
- [ ] 불필요한 의존성이 없는가?

#### 🎨 컨벤션 준수
- [ ] ESLint/Prettier 규칙을 따르는가?
- [ ] 파일/폴더 네이밍 규칙을 따르는가?
- [ ] 커밋 메시지 규칙을 따르는가?

#### 🚀 성능
- [ ] 불필요한 리렌더링이 없는가?
- [ ] 고비용 연산이 최적화되었는가?
- [ ] 메모리 누수 가능성이 없는가?

#### 🔒 보안
- [ ] XSS, CSRF 취약점이 없는가?
- [ ] 민감한 정보가 노출되지 않는가?
- [ ] API 요청에 인증이 적절히 적용되었는가?

### 3.3 리뷰 코멘트 작성법

#### ✅ 좋은 예시
```markdown
✅ **[중요]** `useTimer.ts:42` - setInterval cleanup 누락
`onUnmounted`에서 `clearInterval`을 호출해주세요. 메모리 누수 가능성이 있습니다.

💡 **[제안]** `Avatar.vue:120` - 컴포넌트 분리 고려
아바타 렌더링 로직이 복잡해서 `AvatarRenderer.vue`로 분리하면 좋을 것 같습니다.

👍 **[칭찬]** `useFocus.ts` - 집중도 분석 로직이 깔끔하네요!
```

#### ❌ 나쁜 예시
```markdown
❌ 이거 왜 이렇게 했어요? (이유 설명 없음)
❌ 이 코드 이해 안 돼요 (구체적이지 않음)
❌ 다시 짜세요 (건설적이지 않음)
```

### 3.4 리뷰 우선순위 라벨
- 🚨 **[필수]**: 머지 전 반드시 수정
- ⚠️ **[권장]**: 머지 후 별도 이슈로 처리 가능
- 💡 **[제안]**: 선택 사항, 의견 교환

## ✅ 4. PR Merge 조건

### 필수 조건
- [ ] **최소 1명의 Approve** 획득
- [ ] **모든 [필수] 코멘트 해결**
- [ ] **CI/CD 테스트 통과** (자동화 시)
- [ ] **충돌(Conflict) 해결**

### 권장 조건
- [ ] 2명 이상의 Approve (중요 기능의 경우)
- [ ] QA 테스트 통과 (프로덕션 배포 시)

## 🚀 5. Merge 전략

### 5.1 Merge 방식
```bash
# ✅ Squash and Merge (권장)
# - 커밋 히스토리를 깔끔하게 유지
# - feature 브랜치의 여러 커밋을 하나로 합침

# ⚠️ Merge Commit
# - 커밋 히스토리를 모두 보존 (중요 기능의 경우)

# ❌ Rebase and Merge
# - 선형 히스토리 유지하지만 복잡할 수 있음
```

### 5.2 머지 후 작업
```bash
# 1. 원격 브랜치 삭제
git push origin --delete feature/timer

# 2. 로컬 브랜치 삭제
git branch -d feature/timer

# 3. develop 브랜치 최신화
git checkout develop
git pull origin develop
```

## 📊 6. PR 크기 가이드

### 이상적인 PR 크기
- **변경 라인**: 200~400줄
- **파일 수**: 5~10개
- **리뷰 시간**: 30분 이내

### 큰 PR을 피하는 방법
```markdown
❌ 나쁜 예: 스터디룸 전체 기능 (1500줄 변경)
   - UI + API + 상태 관리 + WebRTC 통합

✅ 좋은 예: PR 분리
   1. PR #1: 스터디룸 UI 컴포넌트 (300줄)
   2. PR #2: API 통신 로직 (250줄)
   3. PR #3: WebRTC 통합 (400줄)
```

## 🔄 7. Draft PR 활용

### 사용 시기
- 아직 작업 중이지만 **피드백이 필요할 때**
- **아키텍처 방향성을 검증**하고 싶을 때
- **WIP (Work In Progress)** 표시

### 작성법
```markdown
## 🚧 Draft PR - 작업 진행 중

### 현재 진행 상황
- [x] UI 컴포넌트 50% 완성
- [ ] API 연동 (진행 중)
- [ ] 테스트 코드 (예정)

### 피드백 요청 사항
아바타 렌더링 방식이 이게 맞는지 의견 부탁드립니다.
```
